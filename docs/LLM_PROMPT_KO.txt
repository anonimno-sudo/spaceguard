전문적이고 프로덕션 준비가 된 방어 중심 안티바이러스 애플리케이션을 설계하고 기본 실행 구성요소를 생성하려고 합니다. 결과물은 Windows 데스크톱을 대상으로 하며 UI는 Electron/Node 기반, 핵심 탐지 엔진 및 실시간 모니터링은 네이티브 C++(또는 C#)로 제안 및 코드 예시를 제공하십시오. 아래 요구사항을 완전히 충족하십시오:

- 아키텍처 및 구성 요소: 실시간 파일 모니터(커널 필터 또는 사용자 모드 워처), 시그니처 기반 스캐너(시그니처 DB 포맷), 휴리스틱/통계적 스코어러, 행위 기반 엔진(이상 동작 감지), 격리(쿼런틴) 관리, 업데이트/구성 서명, 로깅 및 텔레메트리(개인정보 보호 준수).
- 보안/운영 규정: 최소 권한 원칙, 코드 서명, 패키지 무결성, 업데이트 검증, 사용자 데이터 익명화, 관리자 승인/경고가 필요한 중요한 작업.
- 성능 목표: 시스템 유휴 시 CPU 증가는 <2%, 최소 I/O 오버헤드, 병렬 스캔, 스트리밍 스캔, 메모리 제한 및 스로틀 전략.
- 방향성: Windows용 커널 모드 필터 드라이버가 필요한 경우 요구사항과 대안(사용자 모드 + USN/ReadDirectoryChangesW)을 설명하고 서명/휴리스틱 하이브리드 접근 권장.
- 구현 예시: Electron/Node에서 `engine_bridge.js`와 네이티브 엔진 간 IPC 예시, C++에서의 간단한 시그니처 스캐너 골격 및 시그니처 JSON 샘플, `quarantine_manager.js`를 이용한 격리 파일 관리 API 예시.
- 테스트 및 CI: 단위 테스트, 통합 테스트, 퍼징 권장, 성능 벤치마크 명령, 보안 코드 리뷰 체크리스트.
- 출력 포맷: 1) 간단한 아키텍처 문서, 2) 파일/디렉터리 목록과 언어, 3) 최소 실행 가능한 예제 코드 조각(UI<->엔진 통신, 간단한 파일 스캔), 4) 보안 및 배포 단계(코드 서명, 인스톨러, 업데이트 서명).
- 제약: 예시나 제안은 파괴적/악의적 기능(파일 암호화, 데이터 파괴, 백도어)을 포함하지 않아야 하며 방어/탐지/격리 기능만 포함해야 합니다.

요구사항에 따라 아키텍처, 파일 템플릿, 코드 예제 및 CI/테스트 단계를 한국어로 준비하십시오. 두 가지 언어 지원: Türkçe(tr) ve 한국어(ko). UI는 현재 `i18n.js`와 통합됩니다. `docs/` 폴더에 네 개의 파일로 추가하십시오: LLM prompt (TR/KO) 및 Architecture brief (TR/KO).
